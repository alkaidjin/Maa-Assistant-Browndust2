## 一、怎么打开软件

**双击软件根目录里的 `MaaBd2.exe`。** 就这一句。

想从桌面进：右键 `MaaBd2.exe` →「发送到」→「桌面快捷方式」。程序图标已固化在 exe 内，
桌面 / 任务栏直接显示项目图标，无需再手动设置。

> ⚠️ **老用户请注意**：v26.10.1 起**不再有启动器**（`launcher.bat` / `BD2MAA-Updater.ps1`
> / `maintainer.bat` 已全部移除，升级时会自动清掉），且 **`mxu.exe` 已改名为 `MaaBd2.exe`**。
> ① 若你桌面的快捷方式指向旧名字，它会提示“文件已不存在” —— 删掉它，重新建一个指向 `MaaBd2.exe` 的。
> ② **升级到 v26.10.1 这一次，软件内更新可能不会自动重启**：更新程序记住的还是旧名字
> `mxu.exe`，改名后它找不到、就停在“更新完成”这一步。遇到就直接**自己去双击 `MaaBd2.exe`**
> 打开软件 —— 不是更新失败，只是自动重启没成功。从下一版起更新就能正常自动重启了。

## 二、怎么更新（主通道：软件内更新）

MXU（本软件的界面框架）**自带更新通道**，不用装任何外置工具：

1. 打开软件 →「**设置**」→「**更新**」；
2. 有新版时会显示版本号与更新说明，点下载，装完按提示重启软件即生效；
3. 升级**不会动你的 `config/` 配置**（配置目录根本不在发布包里）；
4. 新版里被改名 / 下架的老文件，会按包内的 `changes.json` **自动清掉**（详见第四节）。

通道细节（不影响使用，出了问题再看）：

```json
"mirrorchyan_rid": "Maa-Assistant-Browndust2",
"github": "https://github.com/alkaidjin/Maa-Assistant-Browndust2",
  "version": "v26.10.8"
```

- **版本号与下载源**：检测走 [Mirror酱](https://mirrorchyan.com/zh/projects?rid=Maa-Assistant-Browndust2)（资源 ID `Maa-Assistant-Browndust2`）；
- **买了 CDK**（在 Mirror酱 官网为本项目购买、填入「设置 → 更新」）→ 走 Mirror酱高速下载；
- **没买 CDK** → 自动回退到 GitHub Releases 下载，**完全不影响使用**，只是速度取决于你的网络；
- 新版本由仓库内置的 GitHub Actions 在 Release 发布时自动上传到 Mirror酱，无需人工搬运。
- ⚠️ 购买 CDK 请认准资源 ID `Maa-Assistant-Browndust2`：Mirror酱上另有一个名称相似、
  但与本项目**毫无关系**的第三方项目（名称 `MaaBD2`、资源 ID `MFABD2`），给它买的 CDK 用不到本项目上。

## 四、旧版遗留文件会被自动清理

软件升级是「**覆盖 + 新增**」，包里没有的文件不会被删。所以**文件一旦改名**，
老的那份就会一直留在你目录里 —— 于是可能同时躺着三份同内容的注意事项文档 + 两个教学视频，
既占体积，又不知道该看哪一份。

解决办法是随包派发的清理清单 `retired_files.json`（住在 `data/` 下，列出「以前发过、现在不再派发」的文件）：

- 打包时它会写进包内的 `changes.json`，MXU 更新时按 `deleted` 把清单里的文件移进 `cache/old`；
- 安全边界：只删清单里的**显式相对路径**（含 `..` 或绝对路径一律跳过）、**不碰 `config/`**、
  清单里没写的你自己的文件一律不动、清单缺失 / 解析失败就跳过；
- 你自己想留着某份老文件做纪念？复制到软件目录**之外**即可 —— 清理只发生在软件根目录内。

> ⚠️ 例外：`resource/pipeline/*.json` 这类会被 MaaFramework 当管线加载的文件，
> 光删是不够的（老用户目录里旧文件照样参与加载，跨文件重名会让**整个资源加载失败**）。
> 这类文件要先发一个「同名空壳」覆盖过去，下一版再登记删除 —— 用户侧无需任何操作。

## 五、常见问题

- **「设置 - 更新」里点了检查，说没有新版本，但官网明明发了？**
  版本号由 Mirror酱 提供，新 Release 上传 Mirror酱 需要一点时间；稍等一会儿再查即可。
- **提示有新版本，但没有下载按钮？**
  说明 GitHub 上的压缩包文件名**没能被自动识别**（需要同时含 `win` 与 `x64` 字样）。
  v26.10.1 起的资产名已修正；老版本遇到就按第三节手动下载。
- **更新完版本号没变？**
  先看软件目录里的 `interface.json` 是不是真的没变。多数情况是下载/覆盖被中断
  （`MaaBd2.exe` 正在运行 → 文件被占用）。关掉软件重试一次，或直接走第三节手动覆盖。
- **更新会弄丢我的任务配置吗？**
  不会。`config/` 不在发布包里 —— 新用户首次启动 MXU 自动生成默认实例，老用户的真实实例完整保留。
- **升级后原来的任务卡片怎么少了 / 合并了？勾选项还在吗？**
  v26.10.1 起七张日常卡合并为「一条龙日常」、首轮 / 次轮吸收召集合并为
  「资源吸收和召集（两个轮次）」。旧卡的勾选与选项**自动迁移**，唯一例外：
  **次轮的执行周期需在合并卡里重新勾一次**（默认周二），详见文首 v26.10.1 升级提示。
  启动日志里出现「无效任务被移除 / 无效选项已丢弃」的 WARN 是迁移的正常现象，不是报错。
- **点「开始任务」后秒退 / 报「未搜索到任何窗口」？**
  在 MXU「连接设置」里手动选一次游戏窗口即可恢复。该问题的根因在 MXU 上游，
  v26.09.7 起随包的 MXU v2.5.3 已修复。
- **下载很慢？**
  软件内更新直连 GitHub，国内可能只有几十 KB/s。买 Mirror酱 CDK 走高速通道，
  或用浏览器 / 下载工具从 Releases 页面把 zip 抓下来再手动覆盖。
- **更新完停在“更新完成”，软件没自动打开？**
  只有**升级到 v26.10.1 这一次**会这样：程序从 `mxu.exe` 改名成了 `MaaBd2.exe`，
  更新程序找不到旧名字、自动重启失败。**自己去双击 `MaaBd2.exe` 打开即可** —— 更新本身是成功的。
- **我以前下载的教学视频怎么不见了？**
  教学视频已**永久下架**（分辨率口径收窄为「只支持窗口化 1920×1080」，注意事项文档里的
  速查表 + 截图更准、也不会过期）。升级时它会随 `changes.json` 被自动移进 `cache/old`
  （想留就提前复制到软件目录之外）。设置分辨率的方法看注意事项文档里的截图即可。
- **根目录出现一个 0 字节的乱码文件？**
  来源是**非常旧的** `launcher.bat`（注释里的 `>` 被 cmd 当成重定向符）。
  v26.09.7 起已改写为纯 ASCII、不再产生该文件；老目录里的残留删掉即可，无需干预。

### 解决了哪些问题

1. **任务启动失败 `Tasker not properly initialized`** —— v1.13.1 复用死的 `tasker handle`，手动停止一次任务后下次「开始任务」立刻挂；v2.5.3 在 `!tasker.inited()` 时自动丢弃并重建。
2. **`savedDevice.windowName` 强制门槛** —— 新用户首次启动时等待循环被守卫短路 → `未搜索到任何窗口` 秒退；v2.5.3 守卫改为 `shouldWaitAfterPreActions = !!controller`。
3. **`preAction.args` 引号解析** —— v1.13.1 的 `split_whitespace()` 不识别引号，路径含空格必爆；v2.5.3 改用 `shell_words::split`。
4. **`useCmd` 新增** —— 可显式选择 `cmd /c` 走 .bat，避免把 .bat 误当 PowerShell 调用。
5. **窗口稳定延迟 `preActionConnectDelaySec`（默认 5 秒）** —— v1.13.1 找到窗口后立刻连接，游戏还在加载动画 → 偶发连接错误。
6. **minimaafw 检查** —— v2.5.3 启动校验 `MIN_MAAFW_VERSION = "5.12.1"`，旧版 maafw 启动即报错。
